## 🟡 남은 일 1 — RAG_RELEVANCE_THRESHOLD 실측 재보정 (우선순위 높음)

**왜 중요한가**: `personal_chat_ver1.py`의 `RAG_RELEVANCE_THRESHOLD = 0.5`는
코드 주석에 스스로 "실제 데이터로 검증하지 못한 기본값... 근거 있는 값이 아니다"
라고 적혀 있는 임시값이다. 이 값이 개인 채팅에서 "이론 자료를 근거로 답할지
말지"를 가르는 실제 기준인데, 한 번도 실측된 적이 없다.

**막혀 있던 이유**: 원래 주석엔 "로컬 ADC 재인증이 필요해서 설계 시점엔 실제
쿼리를 못 던져봤다"고 되어 있는데, 이번 세션에서 실제 Gemini 호출을 5번
성공시켰으므로 이 문제는 이미 풀려있을 가능성이 높다.

**해야 할 일**:
1. `calibrate_rag_threshold.py` 실행 (`python3 calibrate_rag_threshold.py`,
   rag/ 폴더에서) — 수영 기술 질문 5개 vs 잡담 5개 각각의 최고 유사도 점수가
   출력됨.
2. 두 그룹 점수 사이에 뚜렷한 경계가 보이면, 그 값을 `personal_chat_ver1.py`의
   `RAG_RELEVANCE_THRESHOLD`(219번째 줄 근처)에 반영.

**왜 이번에 안 했나**: 실제 서비스 동작(개인 채팅이 언제 이론 자료를 근거로
쓸지)을 바꾸는 값이라, 실행 결과 숫자를 사람이 직접 보고 판단해서 넣는 게
맞다고 봄 — 자동으로 값을 바꾸지 않았다. 실행 자체는 실제 임베딩 API 호출이라
약간의 비용이 든다.

## 🟡 남은 일 2 — `prompt_template` / `prompt_template_freer` 중복 구조

두 프롬프트 템플릿(235줄·239줄)이 90% 이상 똑같은 내용을 통째로 중복 보유 —
규칙 하나 고칠 때마다 두 군데를 따로 고쳐야 한다.

**지금 안 하는 이유**: 지금 당장 고장 난 게 아니라 "미래 실수 위험을 줄이는"
성격의 리팩터링이고, 막 10개 규칙을 반영/검증한 직후라 바로 구조까지 바꾸면
문제 생겼을 때 원인 추적이 어려워진다. 공백 하나도 LLM 출력에 영향을 줄 수
있어 리팩터링엔 회귀 테스트(지난번 5개 시나리오 재실행 등)가 필요하다.

**다음에 할 일**: 프롬프트 규칙을 또 크게 손볼 계기가 생기면 그때 공통 부분을
문자열 조립 함수로 뽑아내는 리팩터링을 같이 진행.

## 🟡 남은 일 3 — langchain deprecated 클래스 마이그레이션

`VertexAIEmbeddings`·`ChatVertexAI`·`Chroma` 전부 langchain에서 제거 예정 경고가
뜬다. 확인 결과:
- `langchain-google-genai`(새 LLM/임베딩 클래스)는 이미 설치되어 있음(4.3.2)
- `langchain-chroma`(새 Chroma 클래스)는 **설치 안 되어 있음**

**지금 안 하는 이유**:
1. Chroma 쪽은 새 패키지 설치부터 필요 — 의존성 추가는 별도 결정 필요.
2. LLM 호출 쪽은 이름만 바꾸는 게 아니라 **인증 방식이 달라질 수 있음**(지금은
   GCP 프로젝트+서비스 계정, 새 클래스 기본값은 보통 API 키 방식) — 잘못
   바꾸면 호출이 전부 인증 에러로 실패할 위험이 있어 별도 테스트 환경 검증이
   필요하다.

**다음에 할 일**: 실제로 langchain을 업그레이드해야 하는 계기(지금 1.3.14,
나중에 4.0에서 완전히 제거될 때 등)가 생기면 그때 인증까지 포함해 제대로 검증.
